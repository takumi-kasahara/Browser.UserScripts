# Project Guidelines

This project is a collection of Greasemonkey user scripts that automate and enhance web browsing on popular sites. The project uses modern JavaScript (ES modules) with esbuild for bundling and maintains a modular architecture for code reuse.

## Overview

1. `src/` directory: Contains all source code
   - `src/modules/` - Reusable utility functions used across scripts
   - `src/scripts/` - Individual user script files (*.user.js)
2. `dist/` directory: Generated during build process
   - Contains built user scripts ready for Greasemonkey installation
   - Contains `scripts.zip` for bulk installation
   - Generated by `npm run build:gm` and `npm run build:zip`

## Workflow

### Available Commands

- `npm run build:gm` - Bundles and processes user scripts with metadata headers
- `npm run build:zip` - Creates a zip archive of all scripts
- `npm run build` - Runs both gm and zip build processes sequentially

### Key Tooling

- esbuild: Fast JavaScript bundler
- adm-zip: Zip archive creation
- ESLint: Code linting (configured via `eslint.config.mjs`)
- Node.js ES modules: Uses `"type": "module"` in package.json

## Module Organization

### Core Modules (`src/modules/`)

- DocumentExtensions.js
  - DOM manipulation utilities
- HtmlExtensions.js
  - HTML-specific helpers
- JsonExtensions.js
  - JSON parsing and manipulation
- NavigatorExtensions.js
  - Navigator API helpers (clipboard, etc.)

  - Window utility functions

Scripts are organized by site or functionality:

- Rakuten
  - Rakuten shopping and points automation
- Amazon/Pixiv
  - URL redirection and replacements
- Utilities
  - Cross-site utilities (ISBN conversion, data logging)

## User Script Metadata

All user scripts must include standard Greasemonkey metadata:

```javascript
// ==UserScript==
// @name         Script Name
// @namespace    https://github.com/takumi-kasahara
// @version      1.0
// @description  Short description
// @author       takumi-kasahara
// @match        https://example.com/*
// @icon         data:image/gif;base64,...
// @grant        none
// ==/UserScript==
```

Key metadata fields:

- `@name` - Display name for the script
- `@match` - URL patterns where script runs
- `@grant` - Permissions needed (usually `none` for sandboxed scripts)
- `@version` - Semantic version number

## File Naming Conventions

- User scripts must end with `.user.js` (e.g., `Booklog Edit Date.user.js`)
- Names should be descriptive and indicate the site or functionality
- Use Title Case for readability

## When Adding New User Scripts

1. Create the script in `src/scripts/` with `.user.js` extension
2. Import utility modules from `src/modules/` as needed
3. Add Greasemonkey metadata with proper @match patterns
4. Follow naming conventions - Function names start with verbs, variables with nouns
5. Use JSDoc comments for parameters and return types
6. Export utility functions where possible
7. Run `npm run build` to verify bundling succeeds
8. Test in Greasemonkey with the built version
